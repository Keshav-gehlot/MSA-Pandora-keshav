# Cloudflare R2 (file storage)

**What it is.** Cloudflare's object storage: a bucket of files, S3-like, with no charge for downloads. Free tier:
10 GB.

**Why here.** Pandora already runs on Cloudflare Workers, and R2 attaches to a Worker as a *binding*: the Worker
gets an `UPLOADS` object it can `put` and `get` on, with no API keys and no extra service to sign in to. Each
environment gets its own bucket, so a preview can never touch production files.

**Instead of.** Supabase Storage (used first; it needed two secrets that previews deliberately don't have, which
broke every preview registration) and Cloudinary (built for image transforms we don't need, and weak for private
documents like payment proofs).

**In this repo.**
- Buckets: `pandora-uploads-preview` (every pull-request preview, web and console) and `pandora-uploads`
  (production). Both stay **private**. They're declared in each app's `wrangler.jsonc` (`r2_buckets`).
- `packages/db/src/storage.ts` has the `Storage` type (`putFile`, `getFile`), `diskStorage` for local development
  (`.storage/`) and `r2Storage`. Each app's `src/lib/cf-storage.ts` picks one, like `cf-db.ts` does for the database.
- Only the public site writes (photos, payment proofs, in registration). Only the console reads, through
  `apps/console/src/app/files/[...path]/route.ts`: staff sign-in is required, and payment proofs need an admin.
  Pages link to files with `fileUrl(path)`, which is just `/files/<path>`.
- Files live at `teams/<team id>/photos/<n>.<ext>` and `teams/<team id>/payment/<id>.<ext>`.

**Gotchas.**
- A binding belongs to the request it came from: call `getStorage()` inside the request, never at module level.
- A deployed Worker with no `UPLOADS` binding throws (`DEPLOY_TARGET` is set), instead of writing to a disk that
  would disappear. `wrangler deploy` also fails if the named bucket doesn't exist, so create both buckets first:
  `wrangler r2 bucket create pandora-uploads-preview` and `wrangler r2 bucket create pandora-uploads`.
- The Cloudflare API token needs **Workers R2 Storage: Edit** to create buckets.
